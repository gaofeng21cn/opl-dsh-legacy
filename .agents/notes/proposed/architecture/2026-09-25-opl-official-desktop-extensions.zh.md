# Agent Note: OPL 通过插件增强官方 DSH 桌面版

Status: proposed

[English](2026-09-25-opl-official-desktop-extensions.md) | 中文

## 问题

OPL 用户需要 Gateway 登录、可靠的 Codex 协作和方便的安装入口。当前 fork 把这些能力与桌面壳、Session、Agent loop、权限、Shell 和界面修改一起发布，上游更新因而要求跨域合并、全套构建和桌面签名。继续复制整套桌面产品会使维护投入超过附加功能本身。

本方案的目标是降低长期维护量，同时保留既有成果和数据。源码基线用 `opl-baseline-20260925` 标记；相对于已同步上游的完整文件盘点见[差异清单](../../../../.github/opl-extension-inventory.json)。基线保留现有功能，不等于所有功能已适配官方桌面版。本提案规定迁移顺序，不宣称一键安装器已经交付。

## 提案

### 产品定位与维护边界

OPL DSH 改为“官方 DSH 的增强套件”。官方拥有应用签名、Electron、内置 Host、Agent 循环、会话格式和桌面更新；OPL 拥有插件、Gateway 账号接入、协作协议和安装配置工具。用户看到一个 OPL DSH 安装入口、一个启动快捷方式，以及官方应用里的 OPL 设置页。运行中的应用保持官方名称和签名。

首期只对外发布一个插件组合包 `@one-person-lab/dsh-opl`，内含 Host 插件和 Client 设置贡献，使用 `dsh.bundle.patch` 组合官方插件。网关、协作和偏好在包内保持独立模块和开关，不拆成一批必须各自发布的小包。安装工具与 Codex Skill 随同一套件版本交付。以下名称和命令均为设计目标，不是已发布的下载地址或可用命令。

复用官方公开服务、配置和 slot；不覆盖官方安装目录，不把修改过的 `@deepseek-ai/*` 核心副本偷偷装入 profile，不复制第二份 Cordis 或 Agent loop。没有合适扩展接口的功能单独登记，保留在历史基线；缺少官方支持的功能不会被标记为已迁移。

### 一键安装与用户入口

用户进入本仓库的 OPL DSH 下载页，选择系统，下载并运行“OPL DSH 安装与配置”。首期优先 Apple Silicon macOS，再交付 Windows。优先使用体积小的签名安装工具与系统原生对话框，不新建 Electron 外壳、常驻服务或账号体系。

1. 检测官方 DSH：核验应用身份、版本、架构及实际 profile。已安装可支持版本时复用。没有应用时，只使用经核实的官方分发地址和签名；没有可核实来源时显示官方安装入口并保存当前步骤，不自行改装社区包或退回 fork。
2. 展示安装目标和选项：默认安装 Gateway 双通道；Codex 协作可选；保留官方当前模型选择，提供“将 OPL Gateway 设为默认”的明确选项。已有安装只管理自己拥有的配置。
3. 安装已构建的 OPL 组合包：通过官方插件管理机制写入实际 desktop profile。无源码编译、无 Git、无全局 pnpm 要求。若公开 CLI 是唯一自动化入口，工具携带或下载校验后的兼容 Node，并调用与应用相同版本的官方 CLI；不依赖应用包内部未承诺的路径。这个入口必须通过官方安装包实测后固定。
4. 启用并检查插件：确认 Gateway 页面、两个模型路由、插件版本及鉴权控制端点可用。官方桌面首次引导是否允许第三方 provider，需要作为真实首启验收项；不写入伪造的官方账号或 API key 绕过引导。
5. 用户在 OPL Gateway 页面登录：插件申请或复用本机 DeepSeek/Codex 两组 key。安装器不收集密码，不复制 OPL App 的旋转 refresh token，不改其他客户端 key 的分组。
6. 可选安装 Codex Skill：检测真实 Codex home，复制套件内已构建的 Skill、控制 helper 与配置；保留手工改动，冲突时提供备份及具体处理路径。自动启动指向已验证的官方应用；按当前 Codex 任务 ID 分开记录派发账本。
7. 创建“OPL DSH”快捷方式并显示完成页：快捷方式启动官方 DSH；再次运行安装工具提供“打开、检查、更新增强、修复、移除增强”。未完成登录、运行时不兼容或 Skill 需要重新加载时显示真实状态，不把文件复制成功当成全部就绪。

“一键”指一个产品入口、一次配置流程；系统安装确认、Gateway 登录和明确的权限选择仍由用户完成。安装工具不接管官方自动更新，不需要安装 OPL App 或 OPL Framework。应用内部能否通过公开接口直达 OPL 设置页单独验证；没有接口时正常打开应用并给出“设置 → OPL Gateway”路径。

### 安装数据与失败恢复

官方应用目录只读；官方运行时和 OPL 插件分别更新。OPL 安装记录只存应用标识、版本、目标 profile、套件版本、自有配置项和文件指纹，不存密码或 API key。Gateway key 由 DSH credential store 管理；安装配置不出现 token。协作端点只监听 loopback，连接记录限当前用户读取；本机拥有者与远程执行 Host 分开。

使用官方 profile 写锁与插件管理事务；应用有运行中任务时，等待用户选择稍后应用或结束任务后更新。下载和解包完成后才提交安装；中断后读取实际安装版本与配置继续，避免重复 key、重复任务或重复写入。回滚只恢复本次操作自己改变的插件版本和配置，不回退整个官方 profile。

移除增强只卸载自有组合包、快捷方式和未被用户修改的 Skill 文件。会话、用户配置、凭据和手工修改默认保留；远端 key 的撤销由 Gateway 退出登录操作负责，卸载不等于吊销。更新、修复和卸载均回读官方实际加载结果。

### 版本与维护策略

套件使用独立版本号，发布记录绑定“官方应用版本 + DSH runtime 版本 + OPL 套件版本 + 系统/架构”。首期仅支持已验收的精确版本组合，不默认给任意未来版本兼容豁免。官方自动更新后，插件通过其 peer 约束和启动诊断报告兼容性；不兼容时保留官方应用可用，暂停 OPL 功能并提供匹配版本。

发布产物只需 OPL 插件包、Skill 与小型安装工具。兼容性清单记录官方下载依据、插件文件校验值、公开入口和测试结果；未知下载地址保持未配置，不提供猜测 URL。npm 范围和依赖不得指向我们改写过的上游包；只发布 `@one-person-lab/*` 自有包。两组 key 不等于两个 Harness，模型协议仍由官方 adapter 承担。

CI 必须在没有本仓 workspace 链接的干净官方运行时中安装最终 tarball；禁止以 fork 下的测试替代此项。基础回归覆盖登录状态、双通道、多步工具调用、协作派发/继续/取消/人工等待/重启、Skill 更新冲突和卸载保留。后续官方版本的兼容性检查只测试这些扩展接点，不再跟随每个 commit 合并整仓。

### 旧用户与源码迁移

`~/.dsh-opl` 与官方数据目录保持分离；先允许并行试用，再在用户选择后导入。可映射的偏好经明确字段转换迁移；认证重新建立 DSH 自有登录会话，避免两个产品共用旋转令牌。先扫描并报告会话格式，不自动让官方 V4 打开 V5，也不把 V5 header 改成 V4 冒充兼容。

优先迁移新会话与无损兼容的历史数据。旧版 V5 会话继续由旧版读取，或提供只读 Markdown/JSON 导出；未来恢复为可继续对话的会话必须有单独的转换实现与验收。旧文件和附件保持可恢复，在新链路通过前不卸载旧版。已批准的 V5 是 fork 的功能，不成为新插件路线的前提。

在同一 GitHub 仓库中保留基线标签和历史。先在独立开发分支做最小官方运行时验证；达到下述标准后再将 `main` 转为插件/安装工具的轻量源码树，停止把上游整仓作为主线。旧 fork 只保留恢复用途；新的日常开发与发布只有一条主线。此时再删除已经被验证替代的桌面打包和复制核心代码，不为了完成清单先删除功能。

| 阶段 | 可审阅产物 | 完成标准 |
| --- | --- | --- |

## 考虑过的替代方案

**继续以完整 fork 的 DMG 为默认产品。** 可以最快保留所有现有功能，但无法降低上游合并、核心冲突、跨平台打包和签名成本，仅保留为迁移期间的恢复路径。

**把修改过的整个核心打成“超级插件”。** 用户仍能安装官方壳，但我们继续维护 Session、loop、Shell 和桌面等价层，且更容易出现两套运行时身份；不满足减少维护量的目标。

**只提供一段手工安装命令。** 开发者可用，但不能照顾没有 Node/Git 的普通用户，也没有发现 profile、保护配置、Skill 安装和恢复能力；保留为高级入口，不作为唯一产品入口。

**为每项增强建立独立仓库和发布流水线。** 暂无独立版本需求，增加依赖组合和维护负担；首期一个组合包、内部模块化即可。

## 验收标准

- 在官方签名应用与官方发布 runtime 上运行；应用包校验值不因 OPL 安装而改变，依赖图没有 fork 核心替换或第二份 Cordis。
- 默认 `deepseek-flash` 显示为 `DeepSeek-V4.1-Flash`；两组独立 key、Messages 首选、Responses 首分片前故障切换以及工具只执行一次均有真实证据。
- Codex Skill 能从关闭的官方应用开始，完成鉴权连接、幂等派发、继续、取消、等待人类和读取结果；默认不开启未配置的反向唤醒，也不自动批准 DSH 的权限请求。
- 首次安装、重复安装、升级中断、官方应用升级、移动应用、用户修改 Skill、运行中任务和卸载保留均有端到端结果；不要求用户安装 OPL Framework。
- V5 数据不被官方 V4 误写；旧版仍可恢复。清单中每项增强明确属于已迁移、官方替代、待验证或暂不支持。
- 下载页与安装工具只展示真实可用的官方版本和套件；发布前才能把本提案描述为已实现。

## 风险

截至本次设计，官方源码已证明桌面插件 profile 和内置包管理存在，但报道所指的官方下载渠道尚未核实，最新上游 GitHub Release 没有安装包附件。该事实限制自动下载步骤，不否定插件架构，也不能用源码测试代替官方安装包验收。

官方仍处于预览阶段，公开接口也可能变化。版本矩阵和小范围兼容适配仍需要维护，但其成本应显著小于持续维护整套 fork。若最小验证发现安装器必须改官方私有启动器、核心必须被替换或权限无法保持，就停止该实现路径并报告具体缺口，保留已验证的基线。
