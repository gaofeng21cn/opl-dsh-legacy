# Agent Note: 无需选择工作区的普通聊天入口

Status: implemented

新会话入口策略已被[独立会话项目](2026-09-20-independent-session-projects.zh.md)取代。本记录描述保留的旧聊天预设。

[English](2026-09-20-plain-chat-entry.md) | 中文

## Problem

界面要求先选择工作区才能发送第一条消息，但问答、翻译和写作不需要访问本地项目。

## Decision

会话首页和侧边栏提供普通聊天入口。没有工作区的新安装会打开空白聊天。这些会话使用内置 chat 预设，包含对话角色提示和上下文压缩，不包含面向模型的工具或工作区指令。现有会话创建 API 记录预设，并在内部使用宿主的默认工作目录；不会创建或关联工作区。会话持久化和重启通过现有预设投影恢复记录的配置。

侧边栏把这些会话归入普通聊天，与失去工作区关联的项目会话分开。项目模式选择器和预设管理选项排除 chat。即使尚未发送第一条消息，重新配置也拒绝把聊天切换到其他预设。打开工作区会创建或复用独立的项目会话。

## Alternatives considered

**隐式目录配合标准预设。** 这种方式免去了目录选择，但仍会给普通对话本地工具，不符合界面表达的能力边界。

**新会话格式或第二套聊天数据库。** 现有持久化预设选择已经能够标识会话并恢复其能力，另一套持久化机制会重复职责。

## Consequences

普通聊天无需选择目录，并保留正常的会话历史。它不能浏览网页、操作本地文件、执行命令或委派工作。将已有聊天记录转入工作区暂不实现。自定义宿主插件仍属于受信任的部署代码；此预设限定工具配置，不是操作系统沙箱。
